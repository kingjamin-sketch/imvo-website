IMVO FULL-SITE CMS — OPERATIONS HANDOFF
=======================================

STATUS
------
The full-site Sanity CMS is already integrated in the IMVO repository and is
not a ZIP/manual-install step anymore. Do not copy an old CMS package over the
current website.

Canonical operating blueprint:
  docs/IMVO-CMS-BLUEPRINT.md

CURRENT STUDIO CONTENT
----------------------
The Studio contains:
- Site Settings
- Homepage
- About Page
- Services Page
- Contact Page
- Terms, Privacy and Cookie pages
- Projects

EDITING
-------
Open:
  https://www.imvogroup.com/studio

Use an authorized Sanity account, edit the relevant document and click Publish.
Drafts are not public.

The public site currently caches CMS reads with a 300-second revalidation
window. A normal published change can therefore take up to about five minutes
to appear without a website redeploy.

SEED MISSING PAGE DOCUMENTS ONLY
--------------------------------
If a singleton page document is missing, the repository includes the approved
seed script:

  npx sanity exec scripts/seed-site-content.ts --with-user-token -- --commit

The seed step is recovery/bootstrap tooling, not the normal editing workflow.
Do not use it to overwrite approved Studio content.

CODE CHANGES
------------
Changes to schemas, GROQ queries, Studio structure, rendering logic, routing or
fallback behavior are code changes. Make them on a branch, build/test, review,
then merge and deploy through the normal GitHub/Vercel release flow.

SAFETY
------
- Do not paste Sanity write tokens into website source code or NEXT_PUBLIC_ vars.
- Keep /studio out of search indexing.
- Keep drafts private until Publish.
- Projects stay independent from page singleton documents.
- Preserve coded fallbacks where they already protect the public site.
- Do not put DŌMICILE private operational data in the public website CMS.
- Do not recreate a second CMS/Studio for content already covered by Sanity.
